# 加班打卡 · Android

当前版本 **0.3.4**（versionCode 9）。使用 Kotlin + Jetpack Compose，最低支持 Android 8.0（API 26），目标 Android 16（API 36）。应用与网页共用仓库，通过 JSON 文件互相导入导出；安装包以 Releases 为准。

## 从 Releases 下载安装

日常使用可直接安装正式 APK，无需 Android Studio、JDK 或源码构建环境。

1. 打开 [GitHub Releases](https://github.com/NiceXHZ/calculate_overtime/releases)，进入最新正式版本。
2. 在 **Assets** 中下载 `.apk` 正式安装包，例如 `overtime-checkin-0.3.4-arm64-v8a.apk`。`Source code (zip / tar.gz)` 为源码归档，不是安装包。
3. 在 Android 手机上打开 APK，按系统提示授予当前浏览器或文件管理器安装权限，再完成安装。
4. 打开「加班打卡」，直接记录出勤，之后可添加桌面组件。

安装包以发布页实际提供的附件为准；如果暂无已发布版本或 APK，可等待发布，或按[下方说明自行构建](#从源码构建)。

### 安装包平台

每个文件都是可独立安装的完整 APK，只需选择其中一个，无需安装其他分包。按设备运行的 **Android 系统 ABI** 选择，不按 Windows 主机 CPU 选择。

| 文件后缀 | 适用设备 |
| --- | --- |
| `arm64-v8a.apk` | 常见 64 位 ARM 安卓手机，优先选此版本 |
| `armeabi-v7a.apk` | 仅支持 32 位 ARM 的旧设备 / 系统 |
| `x86_64.apk` | 使用 64 位 x86 Android 系统的模拟器 / 设备 |
| `x86.apk` | 使用 32 位 x86 Android 系统的模拟器 / 设备 |
| `universal.apk` | 同时包含上述四套原生库，不确定系统 ABI 时可选 |

同版本各平台包使用相同签名、包名和 versionCode；这是 GitHub 直接分发策略。跨平台切换仍需设备支持相应 ABI。包体主要为共享 Kotlin/Compose 字节码，原生库很小，按 ABI 拆包主要减少下载和安装体积，不表示同一段逻辑会因此运行更快。

### 升级与切换版本

同一正式签名的版本可以覆盖升级并保留记录与设置。更新前也可以在「设置」导出完整 JSON，额外保留一份外部备份。

**debug 和 release 签名不同，不能直接覆盖安装。** 若此前使用 debug 调试版，请先导出并确认外部 JSON 备份有效，再卸载调试版、安装 Release 页面提供的正式版，最后导入备份。后续正式版升级不需要重复卸载。

## 开始使用

首次启动会自动创建应用内部的 `attendance/overtime_log.json`，无需登录或先导入文件。

| 页面 | 主要操作 |
| --- | --- |
| 今天 | 一键记录当前北京时间，查看今日时间线，撤销刚才的打卡 |
| 记录 | 切换月份，滚轮选择日期与时间补卡，逐条删除，合并导入 JSON |
| 统计 | 查看加班总时长、记录天数、加班天数、日均时长与月历热力图，导出本月 CSV |
| 设置 | 导出完整 JSON、恢复最近副本、修改工作日下班时间、更新节假日、调整外观与反馈 |

应用、桌面组件和快捷磁贴共用 **3 秒**误触保护，达到 3 秒可再次打卡。打卡或补卡后的撤销会核对保存版本；若之后又修改了记录，旧撤销会失效，避免误删其他记录。补卡精确到分钟，不允许选择未来时间；切换月末或闰年时会自动修正无效日期。

日期摘要以 `yyyy/MM/dd` 单行显示，日期与时间滚轮原地切换。补卡、下班时间、每日记录、删除与恢复确认共用圆角玻璃弹层，打开后显示完整操作区；补卡保存按钮固定在底部，中间内容适应窗口高度滚动。可通过关闭按钮、返回键、点按遮罩或拖动顶部关闭。

弹层打开和关闭统一为 480 毫秒，顶部短距离下拉后以 360 毫秒回弹；遮罩跟随拖动变淡。保存、完成、确认和取消使用同一套退出动画，退出期间阻止重复操作。数据修改在确认时立即提交，不等待动画结束。页面和日期／时间滚轮切换以 320 毫秒淡入淡出，遵循 Android 系统动画时长设置。

滚轮支持惯性吸附、选中带、透视淡出、刻度音效和轻震动。声音与震动可分别关闭，遵循系统静音、触摸音效和触感设置；打开弹层或自动修正日期时不触发刻度反馈，滚轮停稳后才能保存。

## 桌面组件与快捷磁贴

| 规格 | 内容 |
| --- | --- |
| 2×1 | 紧凑打卡按钮与最近时间，时间显示到分钟 |
| 2×2 | 最近时间与空间允许显示的较早记录 |
| 3×2 | 今日记录与完整宽度的打卡按钮 |
| 4×1 | 最近打卡时间与横向打卡按钮 |
| 4×2 | 最近时间、较早记录标签与打卡按钮 |
| 4×3 | 更多今日记录与打卡按钮 |

在桌面长按添加小组件，选择「加班打卡」。支持调整大小，六种规格会根据实际空间切换排版；不同桌面的实际格子大小可能不同。设置页也可在桌面支持时请求添加指定规格。

从设置请求添加后，应用会根据桌面成功回调或新增的组件 ID 确认结果；若桌面明确不支持，会直接提示手动添加。请求发出约 6 秒仍未确认时，仅在应用处于前台且没有其他弹层时展示「尚未确认添加成功」，不会把取消操作判为失败。小米、Redmi 和 POCO 手机的提示中附有小米官方添加流程图，可离线打开、缩放和拖动查看。

- **只有打卡按钮保存记录**，点击时间或记录区域进入应用「今天」页。
- 最近时间优先显示，常规尺寸单独显示秒数，较早记录按最近优先排列；空间不足时减少记录数量，保留清晰的时间与按钮。点按记录可查看今日全部打卡。
- 组件跟随应用深浅色，采用高对比底色和中等字重。Android 12+ 优先使用桌面提供的精确尺寸；否则匹配横竖屏尺寸范围，旧版提供横竖屏两套布局。
- 应用修改数据、组件打卡、日期变化和设备重启会触发刷新，另有系统半小时周期刷新。厂商桌面可能延迟周期刷新；更新应用后若仍显示旧布局，可缩放一次组件触发刷新。

在系统快捷设置的编辑界面添加「记录打卡」磁贴，即可快捷记录。锁屏时需要先解锁。

六种小组件和磁贴统一提供结果 Toast：成功显示实际保存时间，3 秒内重复点击和失败各有提示。成功时尝试轻震一次，可在「桌面上的小帮手」关闭 **快捷打卡震动**，与滚轮反馈独立。遵循系统触感、静音和勿扰设置；后台策略或硬件不允许时保留文字反馈，不影响保存。品牌资料、版本降级及限制见[小组件反馈适配说明](docs/WIDGET_FEEDBACK.md)。

## 数据、备份与计算

所有记录保存在本机，不上传打卡数据，不需要账号、定位或通知权限。联网仅用于公开节假日数据。

- 固定按北京时间 `Asia/Shanghai` 分组，手机更改时区后仍使用北京时间。
- 工作日默认计算 **17:30 至最后一次打卡**的时间，早于下班时间为 0；可在设置修改下班时间。
- 休息日有至少两次打卡时取首末间隔，只有一次时为 0；周末调休上班日按工作日处理。
- 不扣午休，不自动配对上下班，不合并跨午夜记录。网页固定按自己的 17:30 规则和浏览器本地时区计算。

JSON 兼容带时区 ISO 字符串、Unix 毫秒整数时间戳、单值及混合数组，保留各月份、空日期、额外字段、毫秒与原有重复打卡。单文件上限 **8 MB**，无效日期、秒级时间戳和跨日打卡会被拒绝。

导入先完整校验再合并，无效文件不改变原记录。同一文件重复导入不会增加打卡，也不轮换修改前副本；同一时间的重复数取两份文件中的较大值，额外字段冲突优先本机。

记录采用原子保存，应用、组件和磁贴共享进程锁。每次修改前保存副本，最多保留最近 **10 次**。恢复最近副本会替换当前记录，操作前有确认；读取失败时保留原文件。健康记录恢复前也会保存当前副本，可再次恢复撤回；损坏原件单独保留，不作为普通副本覆盖。

导入导出使用 Android 系统文件选择器，无需整个存储空间权限，其界面外观由系统与文件管理器决定。导出是当时的数据快照，不会跟随后续打卡自动更新；两端不会自动同步。

**卸载、清除应用数据或换机前，请导出完整 JSON 到应用之外的位置。应用内部的记录和自动副本都会随卸载或清除数据而删除。**

## 外观与离线使用

支持浅色、深色和跟随系统；深色正文和辅助文字使用高对比配色。液态玻璃可在设置关闭。

| 环境 | 应用内玻璃效果 |
| --- | --- |
| Android 13+ | 模糊、镜片折射与高光 |
| Android 12 | 模糊与高光，自动跳过折射 |
| Android 8–11、低内存设备或关闭玻璃 | 不透明圆角材质，保留可读性 |

桌面组件由 `RemoteViews` 托管，使用静态渐变材质，不会实时折射桌面壁纸。

内置 2025、2026 年节假日数据供首次离线使用。数据按年份缓存，超过七天会尝试后台更新，也可在设置手动更新。网络依次使用 jsDelivr 和 GitHub 原始文件；失败继续使用缓存或内置数据，没有对应年份数据时明确提示暂按星期规则计算。读取时合并下一年通知对本年十二月的修正；十二月及历史年份更新会尝试获取下一年通知，缺失时保留本年有效数据。自动更新失败后五分钟内不重复请求，手动更新可立即重试。切换月份不等待旧网络请求。断网仍可打卡、补卡、查看和导出本地记录。

应用时钟仅在有前台界面订阅时按分钟更新，返回应用会立即读取当前时间；月度统计在后台计算，长时间线按需渲染。未添加桌面组件时跳过组件数据和排版更新。

## 从源码构建

需要 JDK 21、Android SDK Platform 36 和 Build Tools 35.0.0。工程使用 Gradle 8.14.4、AGP 8.13.2、Kotlin 2.3.10 与 Compose BOM 2026.02.01，Gradle Wrapper 已包含在仓库内，首次构建和测试需要联网下载依赖。

使用 Android Studio 打开本目录，或在 Linux / WSL 中执行：

```bash
cd android
# 通过 ANDROID_HOME 指定 SDK，或在本地 local.properties 中设置 sdk.dir。
./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

Windows 本机终端使用 `gradlew.bat`。SDK 路径配置只保存在本机，不提交到仓库。

| 安装包 | 用途 |
| --- | --- |
| `app/build/outputs/apk/debug/app-universal-debug.apk` | 调试签名，可覆盖安装使用相同调试签名的旧版 |
| `app/build/outputs/apk/release/app-<ABI>-release.apk` | 配置正式签名后生成；关闭调试，启用代码压缩与资源裁剪 |

本地构建的 APK 可复制到设备自行安装，或在已经连接设备的开发环境中运行：

```bash
adb install -r app/build/outputs/apk/debug/app-universal-debug.apk
```

本地调试包与发布正式包的切换步骤见[升级与切换版本](#升级与切换版本)。源码仓库不包含构建产物；发布时将正式签名 APK 作为 Release 附件上传，签名密钥和密码配置保留在仓库之外。

默认同时生成四种单平台 APK 与通用 APK，调试包也遵循该命名。可通过 `-PsplitApks=false` 临时只构建一个通用包，输出恢复为 `app-debug.apk` / `app-release.apk`。构建保留中文和英文依赖资源；应用正文为中文。

正式包构建后，在 `android/` 中执行：

```bash
python3 scripts/package-release.py
```

脚本逐个验证签名、非调试标记、包名和版本、实际原生库 ABI、16 KB ZIP 对齐与 64 位 ELF LOAD 段对齐，再生成 `app/build/release-assets/v<版本>/`：五个清晰命名的安装包、`SHA256SUMS.txt` 和 `PACKAGE_REPORT.json`。只读取 Gradle 输出清单，不会混入目录中遗留的旧 APK，也不会上传文件。

### 正式签名

在 Linux / WSL 的新环境中首次创建本地正式签名：

```bash
python3 scripts/create-release-key.py
./gradlew :app:assembleRelease
```

脚本使用 JDK 的 `keytool`，将密钥与配置保存在仓库之外，不打印密码：

- 密钥：`~/.local/share/calculate-overtime/signing/release.jks`
- 配置：`~/.config/calculate-overtime/release-signing.properties`

已有配置时脚本直接复用，已有密钥但缺少配置时不会覆盖密钥。Gradle 默认读取上述配置，也可通过环境变量 `OVERTIME_SIGNING_PROPERTIES` 指向自有配置文件。配置包含 `storeFile`、`storePassword`、`keyAlias`、`keyPassword` 四项。

两份文件需一起私密备份，不进入 Git；后续正式升级必须使用同一密钥。没有签名配置的环境执行 `assembleRelease` 只会生成未签名 release，不能将其当作可安装的正式包。
