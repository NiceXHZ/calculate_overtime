# 加班时长计算器

一个无需安装依赖的纯前端小工具。导入 JSON 打卡记录后，可计算本月加班时长、查看每日明细，并管理和导出打卡数据。兼容 iOS 快捷指令生成的时间字符串及旧版网页生成的毫秒时间戳。

## 使用方法

1. 使用现代浏览器打开项目中的 `index.html`，无需构建或启动后端。
2. 点击文件选择区域或拖放 JSON 文件，等待显示「已加载」。可使用仓库中的 [overtime_log.example.json](./overtime_log.example.json) 体验。
3. 点击「计算加班」，查看本月记录天数、加班小时和每日打卡明细。
4. 点击「管理数据」，添加日期及打卡时间，或删除某一天的全部打卡记录。
5. 修改后点击「保存并导出新文件」，将下载的 JSON 保存到本地；如需覆盖原文件，请手动替换。

文件在浏览器本地读取和处理。修改仅保存在当前页面内存中，刷新或关闭页面会丢失未导出的修改，原始文件不会自动更新。

## 计算规则

统计月份取浏览器所在设备的当前年月，目前不支持选择历史月份。

| 日期类型 | 计算方式 |
| --- | --- |
| 周一至周五 | 最后一次打卡晚于 17:30 时，计算从 17:30 到最后一次打卡的时长；否则为 0 |
| 周六、周日 | 至少有两次打卡时，计算最早和最晚打卡的时间差；只有一次打卡时为 0 |

- 每天的打卡时间会先排序，JSON 中不必按时间排列。
- 「记录天数」包含本月有记录但加班时长为 0 的日期。
- 不识别法定节假日和调休，仅按星期判断工作日与周末。
- 不扣除午休、晚餐或中间离开的时间，也不自动按班次配对打卡。
- 日期判断、打卡时间显示和 17:30 基准使用浏览器本地时区；建议在 `Asia/Shanghai`（北京时间）环境使用下方示例。

## JSON 文件格式

文件顶层为对象，键为 `YYYY-MM-DD` 日期，值为包含 `entries` 的对象。导入兼容以下格式：

| `entries` 格式 | 示例 |
| --- | --- |
| 单个带时区的 ISO 时间字符串（iOS 单次打卡） | `"2026-09-10T19:00:00+08:00"` |
| 时间字符串数组（iOS 多次打卡） | `["2026-09-10T09:00:00+08:00", "2026-09-10T19:00:00+08:00"]` |
| 单个或数组形式的 Unix 毫秒时间戳（旧版网页） | `1789038000000` 或 `[1789002000000, 1789038000000]` |
| 字符串和毫秒时间戳混合数组 | `["2026-09-10T09:00:00+08:00", 1789038000000]` |

网页加载后统一整理为**带时区的 ISO 时间字符串数组**，按实际时间排序；新增和导出使用同一格式。转换保留实际打卡时刻、秒和毫秒，不会自动删除重复打卡。导出的时区偏移取浏览器本地时区，在北京时间环境下为 `+08:00`。

推荐格式如下（单次打卡也使用数组）：

```json
{
  "2026-09-10": {
    "entries": [
      "2026-09-10T09:00:00+08:00",
      "2026-09-10T19:00:00+08:00"
    ]
  },
  "2026-09-11": {
    "entries": [
      "2026-09-11T09:00:00+08:00",
      "2026-09-11T17:20:00+08:00"
    ]
  },
  "2026-09-12": {
    "entries": [
      "2026-09-12T09:00:00+08:00",
      "2026-09-12T12:00:00+08:00",
      "2026-09-12T13:00:00+08:00",
      "2026-09-12T18:00:00+08:00"
    ]
  }
}
```

以上内容也保存在 [overtime_log.example.json](./overtime_log.example.json)，按北京时间对应：

| 日期 | 星期 | 打卡时间 | 加班时长 |
| --- | --- | --- | --- |
| 2026-09-10 | 周四 | 09:00、19:00 | 1 小时 30 分钟 |
| 2026-09-11 | 周五 | 09:00、17:20 | 0 小时 |
| 2026-09-12 | 周六 | 09:00、12:00、13:00、18:00 | 9 小时（不扣午休） |

当设备当前月份为 **2026 年 9 月** 且时区为北京时间时，示例应显示 **3 天记录、10.5 小时加班**。其他月份导入该示例会显示本月暂无打卡记录；要体验当月计算，请同时更新日期键和对应时间戳，或加载示例后通过「管理数据」添加本月打卡。

可在浏览器开发者工具控制台中生成时间戳：

```javascript
new Date('2026-09-10T19:00:00+08:00').getTime(); // 1789038000000
```

请使用有效日期和打卡时间，数字必须为**毫秒**时间戳，字符串须包含时区（例如 `+08:00` 或 `Z`）。建议在使用时区下让打卡日期与日期键一致；程序保留原日期键，不会自行将跨日记录移到其他日期。JSON 不支持注释或尾随逗号。

文件格式无效时会提示加载失败，并清空之前加载的数据，避免误算旧文件；请修正文件后重新选择。`entries: []` 会保留在导出文件中，但不计入记录天数。

## 与 iOS 快捷指令配合使用

已有 JSON 可直接导入，不需要手动把时间字符串转换成数字。网页导出后，请将新文件放回快捷指令实际读取和写入的位置。网页无法直接覆盖 iCloud Drive 中的原文件。

iOS 快捷指令后续仍可能把单次打卡保存为字符串，网页可以继续读取；若希望文件始终保持统一结构，请让快捷指令也将单次打卡保存为字符串数组。

## 数据管理说明

- 需先加载 JSON 文件，才能打开数据编辑器；可以加载空对象 `{}` 从零开始录入。
- 编辑器列表仅展示本月记录，导出会保留已加载文件中未删除的其他月份记录和日期对象中的额外字段。
- 「添加」会追加一次打卡，不会自动去重；「删除」会删除该日期下的全部打卡。
- 添加或删除后会自动更新统计；删除全部记录后保持为空，不会重新读取原文件。

