# 数据格式与规则

本页说明网页工具与 Android 应用共用的 JSON 格式、导入行为、计算规则和节假日数据。普通安装与使用方法见 [项目说明](../README.md)，Android 备份操作见 [Android 文档](../android/README.md#数据备份与计算)。

## JSON 格式

顶层使用日期对象，每个日期的 `entries` 保存打卡时间。推荐使用带秒和时区的 ISO 字符串数组：

```json
{
  "2026-09-10": {
    "entries": [
      "2026-09-10T09:00:00+08:00",
      "2026-09-10T19:00:00+08:00"
    ]
  }
}
```

也可以使用[完整示例文件](../overtime_log.example.json)。

`entries` 支持以下格式：

- 单个或多个带时区的 ISO 时间字符串；
- 单个或多个 Unix 毫秒整数时间戳；
- ISO 字符串与毫秒时间戳组成的混合数组；
- 空数组 `[]`，保留该日期，但不参与统计。

日期键须为有效的 `YYYY-MM-DD`。ISO 字符串须包含秒和 `+08:00`、`Z` 等时区信息，数字须为安全整数形式的毫秒时间戳。时间转换到所用时区后，日期须与日期键一致。误用秒级时间戳、无效日期或跨日打卡会被拒绝。

两端导出保留其他月份、额外字段、秒与毫秒，以及文件中原有的重复打卡，并按时间排序。

少数历史时区含秒级偏移，无法用此处的 `±HH:MM` 字符串完整表示；此时导出毫秒整数，避免备份往返时改变实际时间。

## 两端的数据行为

| 行为 | 网页端 | Android |
| --- | --- | --- |
| 导入 | 替换当前加载的数据 | 校验后与本机所有月份合并 |
| 无效文件 | 保留此前有效数据并明确提示失败；首次导入失败仍为空工作区 | 不改变原记录 |
| 编辑范围 | 当前查看月份，可切换历史月份 | 可跨月查看与补卡 |
| 保存 | 更改尝试暂存到浏览器；独立备份需手动导出，不覆盖原文件 | 自动保存至应用内部，可额外导出备份 |
| 时区 | 浏览器本地时区 | 固定北京时间 `Asia/Shanghai` |
| 自动同步 | 不支持 | 不支持 |

### 网页编辑

导入 JSON 或点击「新建记录」后可以编辑。补录范围为当前查看月份，可切换历史月份；不允许新增未来时间或与现有记录完全相同的时间，但导入文件里原有的重复记录与未来记录会保留。导出时保留所有月份。

删除单条打卡保留日期对象和额外字段；删除当天全部记录移除整个日期对象，并明确提示附加字段也将移除。新增或删除后会刷新统计，可撤销最近一次修改；后续修改或导入会使旧撤销失效。

浏览器草稿与源文件分离，恢复需由用户选择。暂存失败会显示提示；检测到其他标签页更新草稿时暂停写入，避免覆盖，支持 Web Locks 的环境还会串行执行跨标签页的检查与写入。清理网站数据会删除草稿，完整 JSON 备份需保存到浏览器之外。

网页同时限制原始文件与规范化后数据为 **8 MB**。临近上限时导出紧凑 JSON，避免因缩进而使备份无法重新导入；超过上限的补录会回滚。CSV 仅导出当前查看月份，包含计算秒数、下班时间与时区，并转义可能被表格软件解释为公式的文本。

### Android 合并与副本

导入先完整校验再合并，同一文件重复导入不会增加打卡。若两份文件在同一时刻分别有多条重复记录，合并取重复数的较大值；额外字段冲突优先本机。两端单文件上限为 **8 MB**。

应用采用原子保存，每次实际修改前保存副本，最多保留最近 **10 次**；重复导入未改变数据时不轮换副本。恢复最近副本会替换当前记录，因此恢复前可先导出当前完整 JSON。读取失败时保留原文件。健康记录恢复前会保留当前副本，损坏记录另存原件供排查。

导出的 JSON 是当时的数据快照，不会随之后的打卡变化。应用内部文件和副本会随卸载或清除数据删除，外部导出备份需自行保管。

## 计算规则

- **工作日**：默认计算 17:30 至最后一次打卡的间隔，早于下班时间为 0。两端均可修改下班时间。
- **休息日**：有至少两次打卡时计算首末间隔，只有一次时为 0。
- **调休**：周末调休上班日按工作日处理，法定假日按休息日处理，优先于普通星期判断。
- 不扣午休、晚餐或中途离开时间，不自动配对上下班，不合并跨午夜记录。
- 有打卡但加班为 0 的日期仍计入记录天数，空数组日期不参与统计。

两端均可切换月份。网页热力图采用固定时长分档：无加班、少于 1 小时、1 至 3 小时、3 至 6 小时、6 小时及以上；休息日只有一次打卡时标为「待补全」。平均加班时长只除以有加班的天数。由于两端时区和下班时间设置可能不同，比较结果时应确认网页处于北京时间、下班时间规则一致。

## 节假日数据

打卡记录不上传服务器；节假日获取会访问公开网络服务。

网页内置 2025、2026 年 `holiday-cn` 安排，可离线使用；已有浏览器缓存优先使用。需要其他年份或刷新时，依次尝试 `holiday-cn`、`china-holiday-calender` 和 Timor，按年份缓存，七天内重复使用。十二月会尝试合并下一年通知中的跨年修正。获取失败继续使用已有安排，没有可用数据时提示按星期规则计算；失败后自动重试有五分钟间隔，用户仍可主动刷新。清理网站数据会移除网络缓存。

Android 内置 2025、2026 年的 `holiday-cn` 数据，按年份缓存，超过七天尝试更新，也可在设置手动更新。网络依次使用 jsDelivr 和 GitHub 原始文件；失败继续使用缓存或内置数据，对应年份不可用时明确提示暂按星期规则计算。
